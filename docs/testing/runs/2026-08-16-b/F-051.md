## Findings

### [S2] An imported image is centred on the world origin, which is the panel's top-left corner

- Where: `defaultLayer` in [reference/controller.svelte.ts:376](../../../packages/ui/src/reference/controller.svelte.ts:376).
- Repro: create any panel, import any image. The layer's `dstQuad` is built as
  `(-w/2, -h/2) → (w/2, h/2)` with the longest side scaled to `DEFAULT_LONGEST_MM = 300`, so the
  image straddles world `(0, 0)`. The panel spans `(0, 0)→(width, height)`, so roughly three
  quarters of the image lands outside the glass, and the user drags it into place on every import.
- Expected: centre the image on the panel — `panelRect(project)` halved, the same precedence
  `defaultSymmetryCenter` already uses (panel size → content bbox → origin).
- Ref: **this is the same root cause as run 2026-08-16-a's F-052 [S1]**, whose fix landed in v0.6.0
  and whose learning is already recorded in `.claude/agents/feature-implementer.md`: _"'Document
  defaults at the origin' is a trap once panels are laid out (0,0)→(w,h): the origin is a corner,
  not a centre. Seed pivots and anchors from `panelRect`."_ Reference import is the second place
  that trap bit; worth grepping for a third.
- Related: the 300 mm default size is arbitrary (the code says so) and unrelated to the panel. Once
  the image is centred on the panel, scaling it to fit the panel's longest side would land it
  roughly where the user wants it before they touch anything.

### [S2] There is no way to rotate a reference layer

- Where: `ReferenceController` — no rotate operation exists.
- Repro: import an image taken slightly off-square (every hand-held photo of a window). Nothing in
  the Draw dock, the Inspector or the on-canvas handles rotates it.
- What exists instead: `scaleFromCorner` (aspect-preserving resize), `dragCorner` (Alt+drag, moves
  one corner freely — a perspective/free transform), `translate` (body drag), `applyCalibration`
  (rescale so two clicked points span a known distance), and the rectify markers.
- Why Alt+dragging corners is not a substitute: it is a free transform, so it **shears** the image
  rather than rotating it rigidly, and hitting an exact angle across four independent corner drags
  by hand is not achievable.
- Ref: `ReferenceLayer`'s own doc comment in
  [model/types.ts:142](../../../packages/model/src/types.ts:142) states that `dstQuad` is what
  "Move/scale/**rotate**/calibrate" transform — so rotation was specified and never built. This is
  a gap against the documented model, not a new feature request.

### [S3] A reference layer has no numeric placement fields

- Where: the Inspector's reference section ([Inspector.svelte:300](../../../packages/ui/src/shell/Inspector.svelte:300)
  onwards) offers opacity, desaturate, lock and scale calibration — no position, size or angle.
- Effect: placement is drag-only. Calibration solves **scale** precisely (two points, a real
  distance) but nothing solves position or angle precisely. Tracing a photo of an existing window
  means matching known dimensions, and a drag cannot be typed or repeated.
- Expected: x / y / width / angle rows in the same `readout` / `field` markup the Draw dock's
  symmetry centre fields now use, in the document's display unit, one undo entry per edit.
