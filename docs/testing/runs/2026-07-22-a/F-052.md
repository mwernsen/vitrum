## Findings

### [S2] Symmetry center point cannot be placed or edited anywhere in the UI

- Where: Layers panel › SYMMETRY (all modes)
- Repro: fresh document → Layers › SYMMETRY → set Mode to any value. Controls offered:
  mirror = Mode + Axis angle + Bake; radial = Mode + Axis angle + Fold count + Add
  mirror + Bake. No center x/y field in any mode; on-canvas dragging of the center/axes
  is explicitly a follow-up, leaving no way at all to move the center off (0,0).
- Expected / Actual: Scope bullet 1 — symmetry "around a center point; axes placeable
  and editable"; Decision §7 — "Radial N-fold config (N, optional mirror, center) lives
  in that same Layers symmetry section". Actual: center is stored in the model
  (autosave shows `center: {x:0,y:0}`) and persisted per FR-4, but is unreachable.
- Consequence: a mirror across the panel's own midline (x=150 on the 300×400 sample
  panel) — the bread-and-butter symmetric-panel workflow — is impossible; the default
  axis lies on the panel's left edge.
- Evidence: dock innerText dump of the SYMMETRY section in both modes (Mode | Axis
  angle | deg | Fold count | Add mirror | Bake symmetry); decoded autosave JSON.
- Ref: FR-4, Scope §1, Decision §7

### [S3] Default center (0,0) puts the whole source domain off-panel

- Where: canvas, mirror mode (default axis angle 90°)
- Repro: fresh sample panel (spans 0..300 × 0..400) → enable Mirror (1 axis) → draw
  anywhere on the panel sheet.
- Expected / Actual: expected to draw on my panel; actually every stored segment is
  canonicalized to the x<0 half — outside the sheet — and the on-sheet linework is the
  read-only replica. Piece detection still works (full network), but the stored truth
  lives off-panel and the tinted "editable" wedge is entirely beside the document.
- Evidence: Inspector after drawing at (+60,50)→(+160,100): Start/End = (−60,50)/(−160,100).
- Ref: FR-5 (works as specified — the finding is the _default_, compounded by S2-1);
  implementation note "Default center = world origin"

### [S3] Clicking a replica is a silent dead click

- Where: canvas, any symmetry mode, Select tool
- Repro: with symmetry on and one line drawn, click precisely on the replica linework.
- Expected / Actual: some feedback (select the source, or a hint that replicas are
  read-only); actually nothing happens — Inspector stays empty, no status message.
  Clicking the source line selects normally. Because of the default-center issue the
  replica is the copy sitting _on_ the panel, so a first-time user's first click on
  their own design silently fails.
- Evidence: click at replica midpoint (world ≈(110,75)) → Inspector empty; click at
  source midpoint → Segment editor opens.
- Ref: Decision §1 / Follow-ups (v1 read-only is intentional — the missing part is any
  feedback); heuristic C (actions give feedback)

### [S3] Saved/Unsaved badge contradicts autosave state (likely owned by the autosave feature, not F-052)

- Where: TopBar document badge
- Repro: (a) change symmetry mode → badge "Unsaved"; wait ~30–60 s doing nothing that
  commits → badge silently returns to "Saved" with no user save. (b) later, undo a bake
  → badge "Unsaved" for 30+ s while the autosave zip in localStorage already contains
  the exact current state.
- Expected / Actual: one coherent meaning (explicit-save state or autosave state);
  actually it flips both ways on no visible rule. During symmetry work I could not tell
  whether reloading would lose the setup.
- Evidence: badge text polled over the session; decoded `vitrum:autosave` matching the
  live setup while badge read "Unsaved".
- Ref: heuristic E; filed here because it was observed on the F-052 flow — probably
  belongs to the autosave/persistence feature's backlog

### [Q] Enter did not finish a line gesture (double-click required)

- Where: canvas, Line tool, browser host via automation
- Repro: L → click → click → press Enter/Return. Gesture stayed live (preview still
  rubber-banding, document count unchanged, badge never dirtied); a later Escape
  silently discarded it. Double-click at the last point commits fine.
- Open question: F-011 says "Enter finishes"; global single-key shortcuts (L, Escape,
  Cmd+Z/K/A) all reached the app from the same focus state, so the Enter handler
  ignoring the same path is at least suspicious — but a synthetic-event quirk of the
  automation harness cannot be ruled out. Worth one manual keystroke to settle.
- Ref: F-011 implementation notes (Enter finishes/applies numeric)

## First-time-user narrative

Turning symmetry on is genuinely delightful: the mode dropdown is exactly where a
document-wide setting should live, the cobalt axis and center dot read instantly, and
seeing the whole rosette redraw live while the readiness pills count along is the
feature selling itself. Bake behaving as one clean undo step — setup restored and all —
felt rock solid, as did drawing in any sector and watching the stroke land in the
source. The worst moment by a wide margin: my first three lines went _missing_ — I drew
on my panel, the ink appeared on the wrong side of the axis, off the sheet, and clicking
the line I could see on my panel did nothing at all. Until I found the Inspector
coordinates I honestly believed drawing was broken. A center control defaulting to the
panel's middle (or any way to move the axis) would turn that first five minutes from
disorienting to magical.

## Suggested learnings

- (F-052, 2026-07-22) The readiness "Checks" pill is a cheap replica-multiplicity
  oracle: one open line contributes 2 dangling-end diagnostics per sector (mirror 4,
  radial-6 12, radial-6+mirror 24).
- (F-052, 2026-07-22) The line tool commits via double-click from the harness; synthetic
  Enter/Return does not finish a gesture and Escape discards it silently — commit before
  judging document state, and verify via the Cmd+K debug palette's segment count.
- (setup, 2026-07-22) Never force-reload with a dirty document + populated autosave:
  the beforeunload/recover prompts can wedge the Browser pane hard enough to take the
  managed dev server down with it. Wait for a clean badge or verify persistence by
  decoding `vitrum:autosave` (base64 zip, `document.json`, deflate-raw) instead.
- (setup, 2026-07-22) `computer` ref-clicks can land on stale coordinates after Svelte
  re-renders; re-screenshot and click by fresh coordinates when a panel toggle seems to
  misfire.
