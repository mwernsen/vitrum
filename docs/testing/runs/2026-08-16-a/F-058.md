## Provenance

Same session as [F-052](F-052.md). Mathieu created a panel from the new-panel dialog to
reproduce a real window, then asked what the dimensions he had typed actually did — because
nothing on the canvas showed them. Confirmed by reading the source.

## Story attempted

Spec's creation flow: the new-panel dialog gives `Project.settings` (name, size, units,
technique) a creation-time UI.

1. ✓ Dialog opens (Cmd+N, and from the library screen), fields present: Name, Width, Height,
   Units, technique radio (lead came / copper foil), "A photo or scan to trace".
2. ✓ Entering a size and technique creates a project with those settings; the library card
   shows the size back.
3. ✗ The panel rectangle is never drawn on the canvas — see finding 1.

## Findings

### [S2] The panel size is invisible: the rectangle is never drawn and never enforced

- Where: canvas render; `settings.panelSize`.
- Repro: create a 300 × 400 mm panel. Nothing on the canvas marks that 300 × 400 area. Draw a
  400 mm line — no outline, no clipping, no diagnostic.
- Cause: nothing in the renderer reads `panelSize`. Its only consumers in the whole repo are
  - [scene.ts:33](../../../packages/ui/src/canvas/scene.ts:33) — zoom-to-fit bounding box,
  - [library.ts:97](../../../packages/model/src/library.ts:97) — the library card's size line,
  - [App.svelte:72](../../../packages/ui/src/App.svelte:72) — re-filling the dialog's defaults.

  No panel outline, no clipping, no DRC rule that the design fits the glass, and no border
  segments seeded from the size.

- Effect: a first-time user reasonably expects the dimensions they typed to appear as the
  drawing frame — that is what the dialog implies. Instead the size is metadata, the user must
  draw the outer border by hand with no reference, and nothing warns when the design overruns
  the glass.
- Expected: draw the panel rectangle on the canvas as chrome (tokens, construction-guide
  weight), so the typed size is visible from the first click.
- Ref: no F-058 FR requires drawing it, so this is a gap between the dialog's implied promise
  and the canvas, not an FR violation. It also makes the F-052 S1 finding worse — the invisible
  rectangle is why the symmetry axes appear to anchor on nothing.

### [S3] Nothing tells the user their design exceeds the panel

- Follows from the above: with no rectangle and no rule, overrunning the glass size is silent
  until the cutting list. A `design-exceeds-panel` DRC rule (F-030 framework) is the natural
  home.
- Filed here rather than against F-030 because the dimension it would check only exists because
  of the F-058 dialog.
